# Rule 22 — <ruby>本文<rt>ほんぶん</rt></ruby>か<ruby>添付<rt>てんぷ</rt></ruby>か — 3つの<ruby>判断基準<rt>はんだんきじゅん</rt></ruby>

>
> キーワード：**「本文か添付かの3基準」**。
>
> **<ruby>関連<rt>かんれん</rt></ruby>：** Rule 65（添付ファイル名を本文で<ruby>明示<rt>めいじ</rt></ruby>）、Rule 66（各添付に1行<ruby>要約<rt>ようやく</rt></ruby>）、Rule 67（<ruby>容量<rt>ようりょう</rt></ruby>10MB<ruby>制限<rt>せいげん</rt></ruby>）。

## 3つの基準
### 基準1 — 長さ
| <ruby>内容<rt>ないよう</rt></ruby>の長さ | <ruby>推奨<rt>すいしょう</rt></ruby><ruby>場所<rt>ばしょ</rt></ruby> |
|----------|---------|
| 5行<ruby>以下<rt>いか</rt></ruby> | 本文 |
| 5〜15行、<ruby>構造<rt>こうぞう</rt></ruby><ruby>明確<rt>めいかく</rt></ruby> | 本文（<ruby>箇条書<rt>かじょうが</rt></ruby>き、<ruby>見出<rt>みだ</rt></ruby>しで） |
| 15〜30行 | <ruby>相手<rt>あいて</rt></ruby>が早く判断する<ruby>必要<rt>ひつよう</rt></ruby>があれば本文、<ruby>参考<rt>さんこう</rt></ruby><ruby>資料<rt>しりょう</rt></ruby>なら添付 |
| 30行<ruby>超<rt>ちょう</rt></ruby> | 添付、本文は要約のみ |

**<ruby>理由<rt>りゆう</rt></ruby>：** スマートフォンで本文30行超はスクロールを<ruby>強<rt>し</rt></ruby>いる — 読み<ruby>疲<rt>つか</rt></ruby>れる。しかし添付は「もう1<ruby>手間<rt>てま</rt></ruby>」（ダウンロードと<ruby>展開<rt>てんかい</rt></ruby>）を<ruby>要<rt>よう</rt></ruby>するので、短い内容を<ruby>ファイル化<rt>か</rt></ruby>するのも<ruby>失礼<rt>しつれい</rt></ruby>。

### 基準2 — 読み方
<ruby>核心<rt>かくしん</rt></ruby>の問い：*相手は<ruby>一度<rt>いちど</rt></ruby>ざっと読むだけか、それとも<ruby>何度<rt>なんど</rt></ruby>も<ruby>参照<rt>さんしょう</rt></ruby>するか？*

| 読み方 | 推奨場所 |
|-------|---------|
| 1回ざっと<ruby>把握<rt>はあく</rt></ruby>、<ruby>後<rt>あと</rt></ruby>で<ruby>戻<rt>もど</rt></ruby>らない | 本文 |
| 後で何度も参照する | 添付（<ruby>保管<rt>ほかん</rt></ruby>しやすい） |
| <ruby>表<rt>ひょう</rt></ruby>データ、<ruby>数値<rt>すうち</rt></ruby>をコピーする | Excelファイル |
| <ruby>画像<rt>がぞう</rt></ruby>・<ruby>図<rt>ず</rt></ruby>・<ruby>組織図<rt>そしきず</rt></ruby> | 添付（画像またはPDF） |
| <ruby>文字<rt>もじ</rt></ruby>のみ、<ruby>複雑<rt>ふくざつ</rt></ruby>な<ruby>書式<rt>しょしき</rt></ruby>なし | 本文 |

### 基準3 — 保管・検索性
**<ruby>正式<rt>せいしき</rt></ruby><ruby>記録<rt>きろく</rt></ruby>として<ruby>保存<rt>ほぞん</rt></ruby>する**必要があるもの（<ruby>契約書<rt>けいやくしょ</rt></ruby>、<ruby>議事録<rt>ぎじろく</rt></ruby>、<ruby>公式<rt>こうしき</rt></ruby><ruby>報告書<rt>ほうこくしょ</rt></ruby>）は<ruby>必<rt>かなら</rt></ruby>ずファイル化。本文は<ruby>体系的<rt>たいけいてき</rt></ruby>な保管が<ruby>難<rt>むずか</rt></ruby>しい — メール本文を Google Drive フォルダに<ruby>入<rt>い</rt></ruby>れて検索、はできない。

| <ruby>種類<rt>しゅるい</rt></ruby> | 推奨場所 |
|------|---------|
| 契約書、<ruby>付属書<rt>ふぞくしょ</rt></ruby> | PDF（<ruby>電子<rt>でんし</rt></ruby><ruby>署名<rt>しょめい</rt></ruby><ruby>付<rt>つ</rt></ruby>きなら<ruby>尚良<rt>なおよ</rt></ruby>） |
| 公式<ruby>見積書<rt>みつもりしょ</rt></ruby> | PDF |
| 議事録、<ruby>決議書<rt>けつぎしょ</rt></ruby> | Word/PDF |
| 数値データ | Excel |
| <ruby>議論中<rt>ぎろんちゅう</rt></ruby>のドラフト | 本文（インラインコメント<ruby>可能<rt>かのう</rt></ruby>） |
| <ruby>進捗<rt>しんちょく</rt></ruby><ruby>状況<rt>じょうきょう</rt></ruby>アップデート | 本文 |
| <ruby>仕様書<rt>しようしょ</rt></ruby>、デザイン<ruby>文書<rt>ぶんしょ</rt></ruby> | 添付（PDF/Word）、本文で要約 |

## 例 — <ruby>同<rt>おな</rt></ruby>じ内容、2<ruby>通<rt>とお</rt></ruby>りの<ruby>整理<rt>せいり</rt></ruby>
### <ruby>状況<rt>じょうきょう</rt></ruby>

<ruby>結果<rt>けっか</rt></ruby>：フオンはスマホで報告書を読めず、PCに<ruby>戻<rt>もど</rt></ruby>るまで読まない。24<ruby>時間<rt>じかん</rt></ruby>ゴールデンウィンドウ（Rule 04）を<ruby>逃<rt>のが</rt></ruby>す。

### 悪い例2 — 全て添付、本文1行

>
> <ruby>第<rt>だい</rt></ruby>19<ruby>週<rt>しゅう</rt></ruby>の報告書を添付いたします。
>
> ズン

## <ruby>鉄則<rt>てっそく</rt></ruby> — 「ファイルには必ず本文要約を<ruby>付<rt>つ</rt></ruby>ける」
**添付ファイルを本文要約なしで送ることは絶対にしない。** <ruby>最低<rt>さいてい</rt></ruby>3文：

> 「[ファイル名]をお送りいたします。[ファイル内容を1文で]。[ご<ruby>注目<rt>ちゅうもく</rt></ruby>いただきたい<ruby>最<rt>さい</rt></ruby>重要ポイント]。」

## 使えるフレーズ
> **「短く→本文。長く、保管性、表があるなら→添付。添付には必ず本文3文の要約を付ける。」**

*使うとき：* <ruby>送信<rt>そうしん</rt></ruby>ボタンを<ruby>押<rt>お</rt></ruby>す前、メールに添付がある<ruby>場合<rt>ばあい</rt></ruby>。本文がファイルを開かなくても**<ruby>行動<rt>こうどう</rt></ruby>できる**情報量を<ruby>持<rt>も</rt></ruby>っているか、ファイルは必要な<ruby>深掘<rt>ふかぼ</rt></ruby>り<ruby>用<rt>よう</rt></ruby>に<ruby>用意<rt>ようい</rt></ruby>されているかを確認する。
